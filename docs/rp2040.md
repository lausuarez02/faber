# RP2040 boards (pocket boards)

Fabwright simulates three RP2040 boards with real arduino-pico firmware: **Raspberry Pi Pico**
(`raspberry-pi-pico`), **Seeed XIAO RP2040** (`seeed-xiao-rp2040`) and **Waveshare RP2040-Zero**
(`waveshare-rp2040-zero`). Decision record: [0003](decisions/0003-round5-see-it-work.md) (C1).

## Use one

```sh
pnpm fabwright new ../my-pocket --template xiao-rp2040   # or pico, rp2040-zero
pnpm fabwright run --ms 2000 -p ../my-pocket              # builds in Docker (first RP2040 build pulls ~1 GB once)
```

- Pin ids are GPIO numbers: `GP0`..`GP29` (`pinMode(25, OUTPUT)` is `GP25`). `connect` also accepts
  `pico.15`, `pico.GPIO15`, and XIAO silkscreen names (`xiao.D4` → `GP6`).
- 3.3 V logic. Power 3.3 V modules from `3V3`, 5 V ones from `VBUS` (silkscreen "5V").
- `Serial` is the board's USB port (the console). Sketches should wait for it:
  `while (!Serial && millis() < 2000) delay(10);` (the templates do), or the first lines are lost,
  as on hardware. `Serial1`/`Serial2` are UARTs on pins and reach parts through the wires.
- Default buses (arduino-pico): Pico Wire GP4/GP5, SPI GP16-GP19; XIAO Wire D4/D5 (GP6/GP7, I2C1),
  SPI D8/D9/D10; Zero Wire GP4/GP5, SPI GP2-GP5. Other pins set with `Wire.setSDA()` etc. are not
  followed by the simulator.
- `export` writes `firmware.hex` and `firmware.uf2`: hold BOOTSEL, plug in, copy the UF2 to RPI-RP2.

## How it works

| Piece | Where |
| --- | --- |
| Backend (rp2040js 1.4.1, core 0) | `packages/sim-backends/src/rp2040/backend.ts` |
| Fabwright's ROM (no Raspberry Pi ROM code) | `rom.ts` |
| Virtual clock, PIO clocking, bit-level I2C target | `clock.ts`, `pio.ts`, `soft-i2c.ts` |
| HEX loader, UF2 writer | `hex.ts`, `uf2.ts` |
| Board pin maps / default buses | `boards.ts` (must match each part.json; a test checks) |
| Build image (arduino-pico 6.3.1) | `toolchains/arduino-pico/Dockerfile`, picked by `services/runner` from the FQBN |
| Board parts | `packages/parts/src/parts/{raspberry-pi-pico,seeed-xiao-rp2040,waveshare-rp2040-zero}` |
| Golden firmware | `packages/sim-backends/fixtures/` (`BUILD.md`) |

Determinism: time advances only in `step()`, by the cycles each instruction takes at the
firmware's clk_sys; `cycles` counts 125 MHz reference cycles. WFE/WFI skip to the next alarm, so
`delay()` is cheap. Same firmware + inputs → same edges on every run (tested under frame slicing).

## Not simulated (also in each fidelity.json)

Core 1 (`setup1`/`loop1`), Raspberry Pi's own ROM code, BOOTSEL/UF2 upload, flash contents across a
reset, I2C target mode, bus electrical detail, non-default bus pins, UART formats other than 8N1,
the temperature sensor (fixed 27 °C), WS2812 LEDs (data runs, nothing drawn), sleep modes. In the
browser the sim runs about 1x real time with a display; the Node sim is ~3x.
